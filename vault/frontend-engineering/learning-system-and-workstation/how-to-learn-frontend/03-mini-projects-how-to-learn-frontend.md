# How to learn frontend (and keep improving) — mini projects

## How to use these projects

Do the projects in order. Each one removes some guidance: the first tells you what to write, the second tells you only what must work. Start in the `starter/` folder, run the tests, and make them pass. Open `solution/` only after your tests pass or after you have used the hints. Read the [[02-lesson-how-to-learn-frontend|lesson]] first.

## Projects

| # | Project | Real use case | Time | Guidance | Open |
|---|---------|---------------|------|----------|------|
| 1 | Ship-It Checker | A team checks CSS/JS features against a Baseline snapshot and prints safe-to-ship or needs-a-fallback | 90 min | guided | `projects/frontend-engineering/learning-system-and-workstation/how-to-learn-frontend/mini-01-ship-it-checker/README.md` |
| 2 | Learning log | A learner scaffolds one read-build-measure-explain note per roadmap item | 2 h | less guided | `projects/frontend-engineering/learning-system-and-workstation/how-to-learn-frontend/mini-02-learning-log/README.md` |

## What each project proves

- **Project 1** proves that a Baseline status decides whether a feature is safe to ship, and feature detection supplies the fallback. How it runs: [[visual-mini-01-flow-how-to-learn-frontend]].
- **Project 2** proves the read-build-measure-explain learning loop by making the learner record every step. How it runs: [[visual-mini-02-learning-log-flow-how-to-learn-frontend]].
