# TC39 proposal stages from 0 to 4

**Sequence** · teaches Spec maturity stages (TC39 Stage 0 to 4), Primary sources over tutorials

**Why this visual.** See that a JavaScript proposal can change until Stage 4, so a tutorial about an earlier stage can go out of date.

Interactive `Timeline`. Open it on the lesson site: `/frontend-engineering/learning-system-and-workstation/how-to-learn-frontend/lesson/02-primary-sources-first/`. Run `npm run site:dev` first.

## What it shows

The TC39 process document lists six stages by number: 0, 1, 2, 2.7, 3 and 4. Only Stage 0 has a name, strawperson; the other labels in the timeline are descriptions, not official names. A proposal can change or stop before Stage 4. Stage 4 needs four things: two compatible implementations that pass Test262, significant in-the-field experience with shipping implementations, a pull request with the integrated spec text, and editor sign-off. Rely on a feature only at Stage 4, and then check browser support.

Text alternative: Timeline of six TC39 stages by number, from Stage 0 (strawperson, an idea) through Stages 1, 2, 2.7 and 3 to Stage 4, where the feature joins the standard, so only Stage 4 features are part of the standard.

## Check yourself

A tutorial teaches a Stage 2 proposal. Why can its code break later?

Answer: At Stage 2 the spec text is a draft, so the syntax can still change or the proposal can stop before Stage 4.
