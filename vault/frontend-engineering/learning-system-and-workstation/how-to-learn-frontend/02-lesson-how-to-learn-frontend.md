# How to learn frontend (and keep improving) — interactive lesson

## Open the lesson

The lesson pages live on the local site at
`/frontend-engineering/learning-system-and-workstation/how-to-learn-frontend/`. Start the site with
`npm run site:dev`, then open that path. Read the pages in order; each one
takes about five minutes. Read the [[01-brief-how-to-learn-frontend|brief]] first.

## Pages

1. `01-the-learning-loop` — The learning loop: read, build, measure, explain. The roadmap's own four-step rule, traced on one feature. Visual: none (planned; an ordering activity instead). Serves outcome 1.
2. `02-primary-sources-first` — Primary sources over tutorials. Specs and official docs do not go stale; TC39 stages say how mature a proposal is. Visual: [[visual-tc39-stages-timeline-how-to-learn-frontend|TC39 stages timeline]]. Serves outcome 2.
3. `03-can-i-ship-it` — Can I ship it? A feature moves from Limited to Newly to Widely available, 30 months later; caniuse tables show the same data. Visual: [[visual-baseline-status-lab-how-to-learn-frontend|Baseline status lab]]. Serves outcome 3.
4. `04-feature-detection-and-polyfills` — Feature detection, polyfills and experimental features. Test for a feature, then run enhanced or fallback code. Visual: [[visual-feature-detect-lab-how-to-learn-frontend|feature detection lab]]. Serves outcome 4.
5. `05-read-other-peoples-code` — Read other people's code. Read with a map, the comments and the call sites, on real Preact source. Visual: [[visual-preact-create-element-walkthrough-how-to-learn-frontend|Preact createElement walkthrough]]. Serves outcome 5.
6. `06-a-weekly-practice-routine` — A weekly routine: practice and staying current. Fixed time for release notes, surveys and practice. Visual: none (planned; a sorting activity instead). Serves outcome 5.
7. `07-build-in-public-and-teach` — Build in public and teach. The path to a first open-source contribution. Visual: [[visual-first-contribution-path-how-to-learn-frontend|first contribution path]]. Serves outcome 5.

More notes, in prerequisite order: [[caniuse-tables-how-to-learn-frontend|Reading caniuse support tables]], [[polyfills-when-needed-how-to-learn-frontend|Polyfills only when needed]].

All visuals: [[visuals-how-to-learn-frontend|all visuals]].

## What you can do after it

1. Explain the read, build, measure, explain loop and run it on one feature. Page 1.
2. Explain why primary sources beat tutorials, and find the right spec section. Page 2.
3. Decide whether a web feature can ship today using Baseline and caniuse. Page 3 and mini project 1.
4. Build a feature check that falls back when an API is missing. Page 4 and mini project 2.
5. Build a weekly routine of practice, news, code reading and teaching. Pages 5–7.

Continue with the [[03-mini-projects-how-to-learn-frontend|mini projects]].
