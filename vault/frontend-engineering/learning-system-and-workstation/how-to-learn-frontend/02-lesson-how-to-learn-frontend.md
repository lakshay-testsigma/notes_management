# How to learn frontend (and keep improving) — interactive lesson

## Open the lesson

Run `npm run site:dev` in the repository root, then open `/frontend-engineering/learning-system-and-workstation/how-to-learn-frontend/` on the local address it prints.

## Pages

1. `01-why-a-method` — Why a learning method matters. Passive tutorial-watching never checks what you learned; a loop exposes the gap. Visual: none (concrete story). Serves outcome 1.
2. `02-the-learning-loop` — The learning loop. Read, build, measure, and explain feed each other and restart the loop. Visual: workflow diagram. Serves outcome 1.
3. `03-primary-sources` — Primary sources over tutorials. Trust a source by its distance from the spec. Visual: source-type map. Serves outcome 1.
4. `04-browser-support` — Know what you can ship. A feature's Baseline label decides ship-readiness. Visual: ship-decision diagram. Serves outcome 2.
5. `05-feature-detection` — Feature detection, polyfills & progressive enhancement. Test the feature, not the browser. Visual: comparison of strategies. Serves outcome 4.
6. `06-practice-and-read-code` — Practice platforms & reading other people's code. Building to a brief and reading a tiny library's call chain beats passive tutorials. Visual: code walkthrough. Serves outcome 5.
7. `07-teach-and-stay-current` — Teach in public & stay current. Publishing and surviving review reveals what you still do not know. Visual: publish-review loop. Serves outcome 5.

## What you can do after it

- Explain the read-build-measure-explain loop and why it beats passive tutorials. — pages 1–3.
- Decide whether a feature is safe to ship today using Baseline and caniuse. — page 4.
- Build a personal learning log that records each roadmap item's four steps. — mini project 2 (learning-log).
- Decide when to polyfill or progressively enhance instead of dropping support. — page 5.
- Explain how reading source code and teaching accelerate frontend expertise. — pages 6–7.
