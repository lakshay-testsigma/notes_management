# Workstation & editor — interactive lesson

## Open the lesson

The lesson pages live on the local site at `/frontend-engineering/learning-system-and-workstation/workstation-and-editor/`. Start the site with `npm run site:dev`, then open that path. Read the pages in order; each one takes about five minutes. Read the [[01-brief-workstation-and-editor|brief]] first.

## Pages

1. `01-why-your-workstation-matters` — Why your workstation matters. A versioned dotfiles repo turns a new machine from hours into minutes. Visual: none (a concrete story). Serves outcome 1.
2. `02-terminal-and-shell-fluency` — Terminal & shell fluency. A pipe feeds one command's STDOUT into the next command's STDIN so small tools combine. Visual: code walkthrough of `curl | grep | awk`. Serves outcome 2.
3. `03-git-and-github-fluency` — Git & GitHub fluency. Merge and rebase join two branches; only the history they leave differs. Visual: branch-and-merge diagram. Serves outcome 4.
4. `04-your-editor-sharpened` — Your editor, sharpened. A setting lives in a scope, and workspace settings are the ones a team commits to share. Visual: two-scope settings map. Serves outcome 1.
5. `05-ai-assisted-development` — AI-assisted development, done safely. Nothing a coding agent proposes reaches the repo until you review, test, and approve it. Visual: review-loop video and a review-gate diagram. Serves outcome 5.
6. `06-node-js-and-version-management` — Node.js & version management. A version manager holds several Node versions and rewrites PATH so the pinned one runs. Visual: nvm to Node versions map. Serves outcome 2.
7. `07-a-production-teams-setup` — A production team's setup. A team standardizes config in version control so every machine agrees. Visual: dotfiles-to-machine workflow diagram. Serves outcome 1.

## What you can do after it

1. Explain why a disciplined, reproducible workstation pays off every day. Pages 1, 4, and 7.
2. Explain what PATH and environment variables do when a command runs. Pages 2 and 6.
3. Build a dotfiles repository that reproduces your setup on a new machine. Mini project 1 and page 7.
4. Decide between merge and rebase for a given branch history. Page 3.
5. Decide how to use an AI coding agent without trusting its output. Page 5.
6. Build a git bisect run that finds the commit that introduced a bug. Mini project 2.
