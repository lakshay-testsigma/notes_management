# Workstation & editor — mini projects

## How to use these projects

Do the projects in order. Each one removes some guidance: the first tells you what to write, the second tells you only what must work. Start in the `starter/` folder, run the tests, and make them pass. Open `solution/` only after your tests pass or after you have used the hints. Read the [[02-lesson-workstation-and-editor|lesson]] first.

## Projects

| # | Project | Real use case | Time | Guidance | Open |
|---|---------|---------------|------|----------|------|
| 1 | Dotfiles | A developer reproduces their whole shell, git, and editor setup on a new machine from one repository and an install script | 2 h | guided | `projects/frontend-engineering/learning-system-and-workstation/workstation-and-editor/mini-01-dotfiles/README.md` |
| 2 | Git bisect hunt | A developer uses `git bisect` to find the exact commit that introduced a bug in a small demo repo | 1 h | less guided | `projects/frontend-engineering/learning-system-and-workstation/workstation-and-editor/mini-02-git-bisect-hunt/README.md` |

## What each project proves

- **Project 1** proves that a versioned dotfiles repo and an idempotent install script reproduce a machine in minutes. How it runs: [[visual-mini-01-dotfiles-flow-workstation-and-editor]].
- **Project 2** proves that `git bisect` turns a manual bug hunt into a binary search over commits. How it runs: [[visual-mini-02-bisect-flow-workstation-and-editor]].
