A notification badge, a stock ticker and a chat all show live data. HTTP lets only the client start a request, so each feature needs a way for new data to reach the browser. The right choice depends on two questions: who sends the data, and how old may it be?

Periodic polling asks the server again every few seconds. It is simple, but each empty check still costs about 850 bytes of headers and cookies. Long polling holds the request open until an update arrives. Server-Sent Events (SSE) keep one HTTP response of type `text/event-stream` open, and the server writes each event into it. The browser reads it with `EventSource`, which reconnects by itself. A WebSocket opens a two-way session: it starts as an HTTP request, upgrades the connection, and then carries messages in both directions without polling.

SSE wins when only the server sends text, because it is plain HTTP and needs no new protocol. WebSocket wins when the client also sends often, as in a shared cursor. Polling wins when a 30-second delay is fine, because one response batches many updates.

**Note.** WebRTC connects two browsers directly, peer to peer, for audio, video and data. Use it for calls, not for server updates.

<Depth level="internals" title="WebTransport">

WebTransport is a browser API that sends data between client and server over HTTP/3. One session carries many streams, one-way or two-way, and each feature can use its own stream. It can also send unreliable datagrams: the network may lose them, and nothing resends them. That suits game state or live positions, where only the newest value matters. A WebSocket gives you one ordered stream only. The limit: the server must speak HTTP/3, and browser and server support is newer than for WebSocket, so keep a WebSocket fallback.

</Depth>

<Depth level="production">

Do the polling math before you ship. Take 10,000 clients that poll and usually get no new data. Each empty request still carries about 850 bytes of HTTP headers and cookies. At one poll a minute the cost is small. At one poll a second the server receives about 60 times more traffic, over 60 Mbps, for no new data. That number is why teams move a busy feed to SSE or WebSocket.

</Depth>
