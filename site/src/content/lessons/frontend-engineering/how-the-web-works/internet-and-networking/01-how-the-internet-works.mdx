You type `https://developer.mozilla.org` and press Enter. Much of the wait before the first byte is the network.

The browser does not send one big message. It splits data into **packets**: small blocks of bytes with a header. The header names the sender and the receiver by **IP address**, a number for each machine on the internet. A **port** number picks the program on that machine, such as 443 for HTTPS. **Routers** read the header and pass each packet one hop closer. Your packets cross several networks that **ISPs** (internet service providers) run. Any packet can get lost.

Two transport protocols run on top of IP. **TCP** opens a connection with a handshake, numbers every byte, resends lost packets and delivers bytes in order. **UDP** sends each packet alone, with no handshake and no resend.

The handshake costs one full round trip. The lost packet blocks every later byte until the resend arrives. This delay is **head-of-line blocking**. HTTP/1.1 and HTTP/2 accept it, because a page needs every byte in order. HTTP/3 runs on QUIC over UDP, so one lost packet stalls only its own stream. DNS lookups and video calls also use UDP, because a fast answer is worth more than a perfect one.

<Depth level="internals">

A new TCP connection does not send at full speed. Slow start lets the sender put only a small congestion window of packets on the wire, then grow it each round trip as acknowledgements return. So a short page load on a fresh connection spends several round trips below the link's capacity. This is one reason browsers reuse connections.

</Depth>
