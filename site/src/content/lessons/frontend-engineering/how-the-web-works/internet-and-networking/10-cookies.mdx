A user signs in to `shop.example.com`, and a form on another site posts to it. Does that request carry the session? If it does, a forged request can spend the user's money.

A cookie is a small name and value, usually at most 4 KB. The server stores it in the browser with a `Set-Cookie` header, and the browser returns it in the `Cookie` header of later requests. Cookies carry session state, preferences and tracking IDs. Each attribute is one check before the browser sends the cookie.

In the lab, change the request and the attributes, and predict which cookies it carries.

<Experience id="cookie-send-lab" />

Domain picks hosts, Path picks URL paths, and Secure requires https. SameSite handles cross-site requests, where the scheme or the registrable domain differs. `Strict` never goes cross-site. `Lax` goes only on a top-level GET navigation. `None` allows cross-site sending and requires `Secure`; the browser's third-party cookie policy can still block it. HttpOnly only hides the cookie from `document.cookie`.

A cookie without `Expires` or `Max-Age` is a session cookie: the browser removes it at shutdown, although session restore can bring it back. `Max-Age` counts seconds and wins over `Expires`. `Max-Age=0` or less deletes it at once. A long lifetime saves sign-ins but gives a thief more time to use a stolen cookie.

**Note.** Name prefixes add checks. A `__Secure-` cookie needs `Secure` and an https page. A `__Host-` cookie also needs no Domain and `Path=/`, so it stays with one host. Use it for session cookies.

<Depth level="production">

Third-party cookies are cookies sent on cross-site requests, often for tracking. Firefox and Safari already isolate or block them by default, so a widget that depends on them can break. When an embed needs state only inside one top-level site, add the `Partitioned` attribute (CHIPS). The browser then keeps a separate cookie jar per top-level site. For storage that the server never needs, use `localStorage` or IndexedDB instead: those values are not sent on every request.

</Depth>

<Depth level="internals">

The `cookie` library behind Express writes strictly and reads leniently. `stringifySetCookie` throws on a Domain such as `example.com; Path=/`, because that value would add a second attribute. The parser drops unknown SameSite values and keeps the first value of a duplicate name (`src/index.ts:135-137 @ a437ef0`, `src/index.ts:292-388 @ a437ef0`, `src/index.ts:439-468 @ a437ef0`).
