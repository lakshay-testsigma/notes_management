A product page needs a user, their last orders and a price list. You can get them in three styles, and each style uses HTTP differently.

A REST-style API is endpoint-based: each resource has its own URL, such as `GET /users/42`. The URL is a unique identifier, so browser caches and CDNs can store the response by its URL. GraphQL is a query language: the client names the exact fields it needs, and the response has the same shape. All operations go to one endpoint, usually `/graphql`, so one request can replace several fetches. RPC (remote procedure call) calls a named function on the server. Connect RPC posts to a URL such as `/connectrpc.eliza.v1.ElizaService/Say` and sends JSON or binary Protobuf, a compact typed message format.

Follow each arrow and see which one reaches the cache.

Only the URL-based request reaches the cache by default. GraphQL servers must accept POST and may accept GET for queries. GET puts the query in the URL, so a CDN can cache it, but long queries can pass URL length limits. Connect works over HTTP/1.1, HTTP/2 and HTTP/3, and it also speaks gRPC and gRPC-Web, so browsers and backend services share one typed contract.
