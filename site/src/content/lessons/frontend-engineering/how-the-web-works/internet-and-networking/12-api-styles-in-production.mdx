A product page needs a user, their orders and prices. Three API styles fetch them, and each uses HTTP differently.

HTTP calls the target of a request a resource, and a URL identifies it (RFC 9110). A REST-style API, in the simple form used here, gives each resource its own URL, such as `GET /users/42`. HTTP caches and CDNs store a GET response by its URL. GraphQL is a query language: the client names the exact fields it needs, and the response has the same shape. All operations go to one endpoint, usually `/graphql`, so one request replaces several fetches. RPC (remote procedure call) calls a named function on the server. Connect RPC posts to a URL such as `/connectrpc.eliza.v1.ElizaService/Say` with JSON or Protobuf, a compact typed binary format.

In practice, only GET responses are cached. GraphQL servers must accept POST and may accept GET for queries; GET puts the query in the URL, but long queries can pass URL length limits. Connect can also send a method marked side-effect free as a GET request, so browsers and CDNs can cache it. Connect works over HTTP/1.1, HTTP/2 and HTTP/3, and it also speaks gRPC and gRPC-Web, so browsers and services share one typed contract.
