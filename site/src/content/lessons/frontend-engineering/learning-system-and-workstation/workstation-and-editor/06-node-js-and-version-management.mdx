You work on two apps: one needs Node 20, the other needs Node 22. A single global `node` can be only one of them. Reinstalling to switch is no way to work. A version manager keeps every version side by side, so switching is one command.

Watch how one version manager holds three versions at once, and which one `node` points to.

A **version manager** such as nvm (Node Version Manager) keeps each installed version in its own directory. `nvm install 22` downloads Node 22. `nvm use 22` rewrites `PATH` so `node`, the JavaScript runtime, resolves to that copy's binary. A `.nvmrc` file in a project's root pins the version, so running `nvm use` there picks the right one. Nothing is deleted when you switch — every version stays installed. **Note.** If the version manager's shell hook is not sourced, `nvm use` runs but `PATH` stays unchanged, so `node -v` still prints the old version.

<Depth level="production">

A Node major moves through a fixed schedule. It starts as **Current** for about six months, then becomes **Long-Term Support (LTS)**, and finally **End-of-Life**. The Node.js project says production apps should run only Active or Maintenance LTS. Those receive critical bug fixes for 30 months. That is why a team pins `.nvmrc` to an LTS major rather than the newest Current.

</Depth>
