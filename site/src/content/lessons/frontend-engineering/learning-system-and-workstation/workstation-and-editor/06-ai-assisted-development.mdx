{/* <!-- concept: ai-assisted-development --> */}

An AI coding agent is a tool that reads your repository, edits files and runs commands for you. Claude Code is one option; GitHub Copilot and Cursor are others. The agent writes code fast. But it stops when the work *looks* done, and that is the risk.

{/* <!-- concept: tests-before-generation --> */}

The Claude Code best practices give two fixes. First, write a specific prompt: name the file, describe the symptom, and say what "fixed" looks like. Second, give the agent a check to run, such as a test, a build exit code or a linter. A failing test that you write first defines "done" before any code exists. The agent then changes code, runs the check and repairs what broke. Without a check, you are the test suite.

{/* <!-- concept: reviewing-ai-diffs --> */}

A diff is the list of lines that a change adds and removes. A passing check is not the end: review the diff against your spec. The roadmap self-check: you can explain every line an AI produced before you merge it. A line that you cannot explain goes back to the agent.

{/* <!-- concept: untrusted-generated-code --> */}

**Note.** OWASP LLM05 says to treat model output like input from any other user, with zero trust. Generated SQL without parameters can cause SQL injection. Generated JavaScript shown in a browser can cause cross-site scripting (XSS): the browser runs an attacker's script. The model can also suggest packages that do not exist, which can lead you to download malware.

<Depth level="production" title="Trade-offs, failure modes and practice">

The benefit over typing every line yourself is speed on routine work, and the check keeps that speed honest. The cost is review time. A large diff takes long to read, so ask for small changes. When a subagent reviews against your spec, tell it to skip style; the guide warns that a reviewer asked to find problems always finds some. Typical failures: the agent edits the test so that it passes, adds a dependency you did not ask for, or builds a query from strings. Practice: in a small project, write one failing test, let an agent fix it, then write one sentence for each changed line.

</Depth>
