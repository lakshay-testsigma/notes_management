A new hire's first pull request passes on their laptop and fails in CI, the server that runs the team's checks. Their Node is 22, the team's is 20. The two machines disagree before the code even runs.

A **dotfiles repo** holds shell, git, and editor config in version control. Watch it turn into machines that agree.

<Diagram id="team-setup-workflow" />

An **install script** in that repo links the files onto each new laptop. A `.nvmrc` file pins Node 20. A **Long-Term Support (LTS)** policy chooses that version, because production apps run only Active or Maintenance LTS. One command on a new laptop, and it matches everyone else.

**Note.** The install script is safe to run twice. It skips a link that already points at the right file. It backs up a real file before replacing it, so a re-run converges instead of duplicating.
