A primary source is the document that defines a feature or the official docs that track it. Examples are a spec, MDN, or the TC39 process document. A tutorial is a copy of a primary source at one moment. When the source changes, the tutorial does not.

JavaScript shows this clearly. TC39, the committee that writes the JavaScript standard, moves each proposal through numbered stages. The process document lists them by number: 0, 1, 2, 2.7, 3 and 4. Only Stage 0 has a name, "strawperson". The other labels below are our descriptions, not official names. A proposal can change or stop before Stage 4. So a tutorial about a Stage 2 proposal can teach syntax that never ships.

Step through the stages below. At each one, ask: "Can I rely on this in production?"

Only Stage 4 means that the feature is part of the standard. You still check browser support next. Before Stage 4, read the proposal itself, not a blog post about it.

The trade-off is speed. A spec is dense and slow to read for a beginner. Start with MDN. When you need the exact rule, open the spec section that MDN links.

**Note.** A common failure is to trust the date on a tutorial. A recent post can still describe an old stage. Check the stage in the source.
