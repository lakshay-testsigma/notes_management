A library does something you did not expect, and the docs do not say why. You can guess, or you can read the code that runs. Reading the source answers the question with the real behaviour, so you stop guessing.

Do not read a repository from top to bottom. Preact's CONTRIBUTING file gives a map first: each package has `src/` for source, `test/` for tests, and `dist/` for bundled build output. Read `src/`, because the build writes `dist/`. Then open one function. Read its JSDoc, the comment block right above it that describes each argument. Last, find its callsites, the places that call it, to see how other code uses it.

Preact is a UI library whose `preact/compat` package mirrors the React API. Its `createElement` function builds a **virtual node** (vnode): an object that describes how an element looks. JSX calls it for you.

export function createElement(type, props, children) {
	let normalizedProps = {},
		key,
		ref,
		i,
		length = arguments.length;
	for (i in props) {
		if (i == 'key') key = props[i];
		else if (i == 'ref' && typeof type != 'function') ref = props[i];
		else normalizedProps[i] = props[i];
	}

	if (length > 2) {
		normalizedProps.children = length > 3 ? slice.call(arguments, 2) : children;
	}

	return createVNode(type, normalizedProps, key, ref, NULL);
}

You saw that `key` never reaches your component's props. That is a fact you can now prove, not a rumour.

The cost is time, and internal code can change between versions. A common failure is reading the wrong file. In mdn/browser-compat-data, the source files still hold `"mirror"` values, while the published `data.json` holds the resolved support data. Read what users actually get.
