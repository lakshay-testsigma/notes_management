Explain is the step most people skip, because the lesson feels finished once the code runs. Publishing on MDN makes it real: you write the page, open a pull request, and a reviewer corrects what you missed. To keep the read step fed, you subscribe to release notes. The core browser set is Chrome, Edge, Firefox, and Safari, so beyond the Chrome for Developers feed you also skim Firefox and Safari release notes and the monthly Baseline digest. Around it you skim a few weekly sources — JavaScript Weekly, Frontend Focus, This Week in React, and the Syntax.fm podcast. Once a year you read the State of JS, State of CSS, and State of HTML surveys.

The loop ends at "Page published", but the review is where you learn. A reviewer checks the writing, not just the code, and asks you to fix what you got wrong. That correction is the explain step doing its job.

The first step is smaller than it looks: pick a task from MDN's task board or a good-first-issue label, claim it, open a pull request, and survive the review. When you are stuck, MDN's own channels — its Discord server and the Learn forum — are where you ask.
