Frontend changes fast. A tutorial can teach an API that changed last year. MDN's front-end curriculum lists constant learning and research among its soft skills. This roadmap turns those skills into one habit: the learning loop. The loop is the roadmap's own convention, not a rule from a source.

The loop has four steps. First, you **read** a primary source, which is the spec or the official docs. Second, you **build** a small demo that uses the feature. Third, you **measure** the demo in DevTools, the browser's built-in tools that inspect and time a live page. Fourth, you **explain** the result in your own words. Each step checks the step before it.

Here is a real case. You want to use the CSS `:has()` selector. You read its MDN page. You build a form that turns red when it has an invalid input. You open DevTools and see which rule applies. Then you write two sentences on what `:has()` matches. Compared with copying a snippet, you now know why the code works.

The loop costs more time than a copy and paste. It is worth it for features that you will use often.

**Note.** The loop fails when you skip measure. Then your explanation repeats the docs and never tests them.

<Depth level="production">
Pick the size of the demo with care. A demo that has more than one new feature hides which feature caused a result. Keep one new idea per demo, and keep the rest of the code familiar. When the measure step shows a surprise, go back to read before you change code. The surprise usually means that you missed a condition in the source.
</Depth>
