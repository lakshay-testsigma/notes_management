Tutorials show the happy path and stop there. A practice platform such as Frontend Mentor turns that into a loop: choose a challenge, build it your way, submit it, and level up. The other half is reading a tiny library line by line, because a summary hides the decisions.

When the goal is a job, the loop turns into interview-style drills. GreatFrontEnd and BFE.dev drill UI components and system design, JavaScript30 is a vanilla build, and CSS Battle is a layout under a constraint. MDN pairs that practice with a structured route: its Learn web development modules and skill tests. It also lists job-oriented courses — Scrimba, freeCodeCamp, and Codecademy.

Here is the core of nanoid's `index.js`, a 174-line file reduced to the lines that make an id. Step through it and predict what each random byte becomes.

let urlAlphabet =
  'useandom-26T198340PX75pxJACKVERYMINDBUSHWOLF_GQZbfghjklqvwyzrict'
let random = (bytes) => crypto.getRandomValues(new Uint8Array(bytes))
let customRandom = (alphabet, defaultSize, getRandom) => {
  let mask = (2 << (Math.log(alphabet.length - 1) / Math.LN2)) - 1
  let step = -~((1.6 * mask * defaultSize) / alphabet.length)
  return (size = defaultSize) => {
    let id = ''
    while (true) {
      let bytes = getRandom(step)
      let j = step
      while (j--) {
        id += alphabet[bytes[j] & mask] || ''
        if (id.length === size) return id
      }
    }
  }
}
let customAlphabet = (alphabet, defaultSize = 21) =>
  customRandom(alphabet, defaultSize, random)
let nanoid = (size = 21) => customAlphabet(urlAlphabet, size)()
`}

A call to `nanoid()` reads 21 secure random bytes and masks each to 6 bits. Every byte becomes an index from 0 to 63, which picks one of 64 URL-safe symbols. That is why every id has 21 characters and 126 random bits — the part a summary leaves out.

Reading is only half the habit. To cement it, close the tab and re-implement a 50-line version from memory: zustand's core store, `Promise.all`, or a `debounce`. Then test your version against the real library.
