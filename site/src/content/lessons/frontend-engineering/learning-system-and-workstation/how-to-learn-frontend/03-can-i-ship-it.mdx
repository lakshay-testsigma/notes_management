A feature in the spec is not yet a feature in your users' browsers. Before Baseline, you read a support table for each browser and judged the result yourself. Baseline gives each web feature one label instead.

The label depends on the core browsers: Chrome, Edge, Firefox and Safari, plus Chrome, Firefox and Safari on mobile. If one core browser lacks the feature, it has **Limited availability**. When the last one ships it, it is **Newly available**. After 30 more months, it is **Widely available**. Shipping in the last core browser moves the label to Newly available; after that, only time moves it to Widely available.

In the lab, pick a scenario and step through it with Back and Forward. At each step, predict the label before you look.

<Experience id="baseline-status-lab" />

You saw the label stay at Limited availability while one browser was missing. You also saw it move to Widely available only after month 30.

For the detail, open caniuse. Its tables show each browser version in a color: green is supported, red is not, greenish yellow is partial, and gray is unknown. The data behind MDN's tables, the browser-compat-data project, is also used by caniuse.

The benefit is speed: one label replaces a check of many browsers. The trade-off is reach. Widely available means most sites, not all sites. The core set leaves out other browsers and old versions.

**Note.** A common failure is to ship a Newly available feature with no fallback. Some users still run older browsers, so check your own analytics.
