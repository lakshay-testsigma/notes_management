**Feature detection** asks the running browser one question: do you have this feature? In CSS you write `@supports (grid-template-columns: subgrid)`. In JavaScript, `CSS.supports("grid-template-columns", "subgrid")` returns the same answer. The page keeps two versions: the richer layout and a plain fallback. It applies the one that matches, which is **progressive enhancement**. When no test can detect a feature, you reach for a **polyfill**, JavaScript that adds the missing behaviour. **Browser sniffing** reads the user agent string and branches on the browser name. MDN calls it a terrible practice, because a browser can hide its name.

**Note.** `@supports` needs no JavaScript and makes fewer HTTP requests, so MDN prefers it for CSS support checks.

Before a feature reaches Baseline, you can try it early: turn it on behind a browser flag such as **chrome://flags**, watch its status climb on **Web Platform Status**, or join an **origin trial** to test it on a live site. The same progressive enhancement rule applies — keep a plain fallback, because an experimental feature can be off or gone in the next release.
