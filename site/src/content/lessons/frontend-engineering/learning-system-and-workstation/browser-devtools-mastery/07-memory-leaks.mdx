Your single-page app gets slower after each route change. In the Chrome Task Manager (Shift+Esc), the JavaScript Memory column rises with every visit. That steady rise is a memory leak: memory grows because of a bug, not because the page needs it.

The garbage collector frees an object only when no chain of references leads to it from a GC root. A GC root is a starting point that is always alive; the global `Window` hangs from it. A leak is an object that you meant to drop while some chain still reaches it. A heap snapshot, taken in the Memory panel, is a picture of every reachable object at one moment.

Before you watch, put the leak hunt in order.

The undo matters. If the count still grows after the undo, something holds a reference. The Retainers section lists the objects that point to the selected object. Trace the path below from GC roots to the list, and name the reference to remove.

<Diagram id="detached-node-retainer-path" />

The code removed the `ul` from the page, so it is a detached DOM node: out of the document tree, but still referenced from JavaScript. The variable `detachedTree` is its retainer. Set it to `null` and the browser frees the `ul` and its ten `li` children. Without snapshots you guess which cache or listener holds memory; the Retainers path names the exact reference. The cost is a pause while Chrome writes the snapshot.

<Depth level="internals">

Shallow size is the memory an object holds itself. Retained size is the memory you free by deleting it, because what depends on it becomes unreachable. A small object can have a large retained size, so sort by retained size. Distance is the length of the shortest path to a root. Right-click a retainer and choose "Ignore this retainer" to see what else holds the object. A snapshot does not capture numbers or getters that run native code.

</Depth>

<Depth level="production">

When you do not know which action leaks, record the Allocation Timeline instead. Each blue bar is new memory in the JavaScript heap, so each bar is a candidate leak. Zoom on a bar to filter the Constructor pane to objects created in that window. The docs give no fixed limit for too much memory: it depends on the device, so test on the devices your users have.

</Depth>
