You deploy a fix, but one tester still sees the old page. Another tester logs out and still sees a full cart. The bug is not in your code. It is in state that the browser saved earlier.

The Application panel shows that saved state. Its Storage section lists three areas. Cookies are small named values for one site. IndexedDB is a database inside the browser for large structured data. Cache storage holds saved request and response pairs. You can open each area, read an entry, edit it, or delete it.

A service worker is a script that the browser runs between the page and the network. The Network panel shows this as the "Request to ServiceWorker" phase of a request. A worker can answer from Cache storage, so a stale cache serves old files after a deploy. Check the Service workers and Cache storage panes before you blame the server.

<Depth level="production">

The Back/forward cache tab runs a test on the current page. The back/forward cache (bfcache) keeps a page you left, so the Back button restores it without a reload. The test lists each reason the page cannot enter that cache. Under Background services, the panel also lists speculative loads: pages that the browser loads before a likely navigation. The trade-off: these caches make navigation fast, but they also keep old state alive, so test both paths.

</Depth>
