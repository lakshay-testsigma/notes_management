You type "re", then "rea" into a search box. The results show matches for "re". Two `fetch` calls ran, and the slower, older response arrived last. Your editor debugger cannot pause this page. The Sources panel can: it is the DevTools debugger for the live page, with real network timing.

A breakpoint type decides when the page pauses. A line breakpoint pauses on one line. A conditional breakpoint pauses only when an expression is true, such as `query === "re"`. A logpoint prints a message and does not pause, so you log without editing code. An XHR/fetch breakpoint pauses when a request URL contains a string. Others pause on a DOM change, an event, an exception or a function call. Use them when you do not know which line to break on.

<Depth level="internals" title="Breakpoints for an unknown line">

A line breakpoint or a `console.log` needs a known line. These types find the line for you, and you do not edit or reload code.

- **Unknown thrower.** In the Sources panel, check "Pause on uncaught exceptions" or "Pause on caught exceptions". DevTools pauses on the line that throws.
- **Unknown script changes a node.** In the Elements panel, right-click the node, select **Break on**, then **Subtree modifications**. DevTools pauses on the code that adds or removes a child.
- **Unknown click handler.** In the Event Listener Breakpoints pane, check `click`. DevTools pauses in the listener code that runs after the event.
- **Noisy line.** Exception breakpoints can stop again and again on one exception you do not care about. Right-click that line and select **Never pause here**. It is a conditional breakpoint with a false condition.

</Depth>

In the lab, choose a breakpoint type and run the race. When the page pauses in the response handler, read the Call Stack and the Scope pane. The async call stack adds the frames that scheduled the callback, so you see which `search()` call sent this response.

<Experience id="debugger-lab" />

Frames from framework or bundler code are ignore-listed: DevTools hides them in the call stack, so your own frames stand out. Turn on "Show ignore-listed frames" when the bug is inside a library.

**Interpretation.** A pause changes timing, so a line breakpoint can hide a race. A logpoint keeps the page running and shows the real order.

<Depth level="internals">

A source map can carry an `ignoreList` field: indices into its list of sources that tools may hide when you step through code. The ECMA-426 standard says it only advises tools; it does not force them. The Scope pane shows local, closure and global variables of the paused frame, and you can edit a value there to test a fix.
