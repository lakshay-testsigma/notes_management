A button on your checkout page is in the wrong place, and a request to the server fails. Your source code says what should happen. It does not say what the browser actually did. Browser DevTools are the tools built into Chrome, Firefox and Safari that show you what the browser did: the live page, its requests, its JavaScript and its memory.

DevTools split this work into panels. A panel is one tab that shows one kind of fact. Elements shows the DOM, the tree of elements that the browser builds from your HTML. Network shows every HTTP request, the message that the browser sends to a server for a file or for data.

The diagram maps a symptom to the panel that shows its cause. Read one symptom on the left, then follow its arrow.

So you start from what you see, not from a list of tools. This is faster than the usual alternative: you guess, add `console.log` lines, reload and read again. DevTools read the real state of the page without a change to your code.

<Depth level="internals">

Chrome DevTools is itself a web app, written in TypeScript and CSS. Its panels send commands to the page through the Chrome DevTools Protocol and get back DOM, network, JavaScript and memory data. A Puppeteer script uses the same protocol, so a check that you do by hand can later run as an automated test.
