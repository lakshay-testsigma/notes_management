A product page feels slow, but only for some users. Without a recorder you can only guess: is the server slow, the file large, or the phone network bad? The **Network panel** records every request the page makes while DevTools is open, with one row per request.

The **waterfall** is the column of bars beside those rows. Each bar shows when a request started and how long it took. The lighter part of a bar is time spent waiting, and the darker part is time spent downloading. Click one row and open its **Timing** tab to see the bar split into named phases.

Each phase starts only after the one before it ends. **Time to first byte** (TTFB) is the wait from sending the request to receiving the first byte of the answer.

**Interpretation.** A long Waiting phase points at the server. A long Content Download points at file size or the network. A long Queueing phase points at too many requests competing for connections.

Now change the conditions yourself. Pick a throttling preset or turn off Disable cache, and watch which phases grow.

<Depth level="internals">

The Initiator column names what started a request: the HTML parser, a redirect, a script, an HTTP 103 Early Hints response, or Other, such as a typed URL. For a script, it links to the source line. Hover the cell to see the stack trace that sent the request. Hold Shift and hover a row: DevTools colors initiators green and dependencies red. The first green row above is the initiator, and a green row above that is its initiator. Use this chain when a file loads late, to see which file had to load first.

Right-click the table header to add the Priority column. With Settings > Big request rows, it shows the initial priority (bottom value) and the final priority (top value). A low priority explains a long Queueing phase: the browser sent higher-priority requests first.

</Depth>

<Depth level="production">

Right-click a row and choose Copy > Copy as cURL or Copy as fetch. You get the same request as a command. Run it in a terminal or in Node.js to replay a failing API call without the UI, or send it to a backend developer as an exact repro.

A HAR (HTTP Archive) file is JSON that holds every recorded request. Export HAR (sanitized) leaves out Cookie, Set-Cookie and Authorization headers. Export with sensitive data needs a setting first, and that file can hold session cookies and tokens, so treat it as a secret. A teammate can drag a HAR into their Network panel and read the same waterfall.

The Network request blocking tab in the drawer blocks a URL, so you see how the page behaves without it. Check Disable cache to see what a first-time visitor loads. A "Provisional headers" warning means the request came from cache or was invalid, so the Headers tab may be incomplete.

</Depth>
