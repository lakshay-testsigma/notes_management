Your page feels slow, but you do not know where to start. The Lighthouse panel runs an audit: an automatic check that loads the page and reports a score for Performance, Accessibility, Best Practices and SEO. Each score comes with the issues behind it.

The Performance score is a weighted average of five metric scores. Total Blocking Time (TBT, how long the main thread blocks input) has weight 30. Largest Contentful Paint (LCP) and Cumulative Layout Shift (CLS) have 25 each. First Contentful Paint and Speed Index have 10 each. Each metric gets a score from 0 to 1 on a curve built from real-site data.

Two other tools find the cause. The Coverage panel records which bytes of each JS and CSS file ran: gray bars are unused bytes. The Rendering tab flashes repainted areas green, highlights layout shifts in purple, and emulates user settings such as dark mode or reduced motion.

**Note.** Lighthouse in DevTools depends on your machine, extensions and stored data. Do not compare two runs from different machines.

<Depth level="internals">

Lighthouse fits a log-normal curve through two points per metric: the 10th percentile and the median of real sites, with separate mobile and desktop values (`core/audits/audit.js:89-109 @ 3b399f6`). The weights live in `core/config/default-config.js:419-424 @ 3b399f6`. If one audit fails, its score is null, and the whole category becomes null instead of a misleading partial average (`core/scoring.js:22-42 @ 3b399f6`).

Navigation mode audits a fresh load. Timespan mode audits a period of interaction. Snapshot mode audits the current state.

</Depth>

<Depth level="production" title="Which panel for which job">

The DevTools docs recommend the Performance panel for deep performance work and Lighthouse for the other categories. Teams run Lighthouse CI on separate servers for comparable runs. Coverage only finds unused code; removing it is a separate refactor. Open each panel below from More tools or the Command Menu.

- **CSS Overview** reports all colors, fonts, unused declarations and media queries of the page, plus low-contrast text. Click an entry to see its elements. One report replaces reading rule after rule in Elements.
- **Recorder** records a user flow, such as a checkout, and replays it. Measure performance replays the flow into a Performance trace, so each test repeats the same clicks.
- **Layers** shows the rendered layers in 3D. Slow scroll rects marks scroll listeners that can slow scrolling.
- **Issues** groups browser warnings such as cookie problems, mixed content, CORS errors and CSP violations, each with a fix. The Console shows the same warnings in a less clear form.
- **Animations** and **Privacy and security**: this lesson did not verify their pages today, so it does not describe them.

</Depth>
