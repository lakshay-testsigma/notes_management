A layout works in Chrome on your laptop, but a tester says it breaks on an iPhone. Chrome's device mode cannot show this bug. Device mode only approximates a phone on your desktop CPU, and it still uses Chrome's engine. You need the real browser on the real device.

Device mode still has a job. It is the device toolbar in Chrome DevTools: it resizes the viewport and throttles the CPU and network. Use it for fast layout checks, then confirm the result on the real phone.

Each browser has its own inspector. Firefox DevTools draws strong layout overlays. The Grid inspector shows line numbers and area names. The Flexbox inspector explains why an item has its final width. The Accessibility inspector shows the tree of roles and names that a screen reader gets. Safari's Web Inspector is the inspector you need for Safari on iOS.

Remote debugging means that a desktop inspector attaches to a browser on a phone. Click each desktop node and read the steps on its connection.

Each pair is a fixed chain of switches on both ends. When a phone does not appear, check the missed switch or the prompt on the phone first. After the connection works, you use the familiar panels, and they act on the phone's page.

<Depth level="production">

In Responsive mode you drag the viewport edges or click a width preset from Mobile S (320px) to 4K (2560px). The Dimensions list sets the size of a named device instead. Low-end mobile throttling gives slow 3G and a CPU 6 times slower. It slows your laptop, so it does not match a real phone. The Sensors panel overrides geolocation with a preset city, your own coordinates, or Location unavailable to test the error path. It also sets device orientation from presets or alpha, beta and gamma values. So you test a map or a tilt feature without travel. The docs call device mode a first-order approximation: a mobile CPU has a different architecture, so profile on a real low-end phone. Turn off sleep on both screens and avoid USB hubs. The DevTools version that opens matches the Chrome version on the phone. The roadmap names device clouds such as BrowserStack, LambdaTest and Sauce Labs; this lesson does not evaluate them.

</Depth>

<Depth level="internals">

The Firefox Accessibility inspector runs an engine in the background while it is open. It can skew Memory and Performance measurements, so close it before you profile. Its tabbing-order overlay is static and does not follow later page changes. iOS simulators always allow remote inspection and appear in the Develop menu like a real device.

</Depth>
