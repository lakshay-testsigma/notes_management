A shopper clicks "Add to cart" and nothing happens for half a second. You feel the lag, but you cannot see its cause. The Performance panel shows it. A trace is a recording of everything the browser did for a few seconds: scripts, style, layout and paint.

When you open the panel, the live metrics screen shows three Core Web Vitals. LCP (Largest Contentful Paint) is when the main content appears. CLS (Cumulative Layout Shift) is how much content jumps. INP (Interaction to Next Paint) is how fast the page answers a click. Turn on field data to compare your local values with CrUX, Chrome's data from real users. When a problem repeats, record a trace.

The main thread is where almost all your JavaScript runs, and it runs one task at a time. A task over 50 ms is a long task. While it runs, the page cannot answer the next click. Play the animation and watch one click become a long task.

The flame chart draws this as boxes. Time runs left to right, and each call sits under the call that caused it. Scripting is yellow and rendering is purple. Now use the lab: throttle the CPU, predict which task crosses 50 ms, and watch INP change.

<Experience id="performance-panel-traces" />

**Note.** CPU throttling slows your own machine by a factor such as 2x. It cannot truly copy a mobile CPU, so compare your trace with field data before you trust a number.

<Depth level="internals">

Click a box in the Main track to see its duration, self time, source link and stack trace. Self time is the time a function spent itself; total time adds its children. The Bottom-up table sorts by self time, and the Call tree shows which root activity caused the most work. Other tracks help too: the Interactions track puts a red triangle on interactions over 200 ms, and the Layout shifts track shows each shift as a purple diamond.

</Depth>

<Depth level="production">

The benefit over timing code by hand is that one recording covers loading, scripts and rendering, with no code change. For a slow first load, use Record and reload: DevTools opens about:blank, reloads, and stops a few seconds after load. The Insights tab in the left sidebar lists the insights that Lighthouse also reports, such as LCP and INP subparts, third parties, and duplicated JavaScript. Failed insights get their own sections, and passed ones collapse at the bottom. Click an item, and the panel highlights the matching events in the trace. So you go from advice to the exact task. The reference says that you can annotate a recording and share it, but it leaves the steps to a separate guide. The reference does not mention Long Animation Frames, so this page uses only its long-task marks. The fix for a long task is usually to split it and yield to the main thread.

</Depth>
