A bug report says "the site feels heavy, and dark mode looks broken". Each remaining panel measures one kind of problem. Find the problem on the left of the map, follow its arrow, and name the panel.

<Diagram id="symptom-to-panel-map" />

Lighthouse is an automated auditor in the Lighthouse panel. First it gathers: it loads the page and records a trace and a log. Then audits read those records and score the page. Teams run it in continuous integration, so a regression shows before release.

Coverage records which bytes of each CSS and JavaScript file ran. Unused bytes are code to split or remove. Rendering emulates user settings such as `prefers-color-scheme`, `prefers-reduced-motion`, `forced-colors` and `prefers-contrast`. You test dark mode without a change to your operating system. Recorder records a user flow, then replays it, measures it, and lets you edit its steps. You stop clicking it by hand after each fix.

Device mode simulates a phone from your laptop. The device toolbar sets a responsive viewport or a device preset, a device pixel ratio (DPR, the number of screen pixels per CSS pixel), and CPU and network throttling. It is only a first-order approximation: your code does not run on the phone, and a mobile CPU has a different architecture. Confirm the result on a real device (page 11).

<Depth level="internals">

The gather phase saves artifacts; the audit phase reads them. The CLI flag `-G` stops after gathering and `-A` audits saved artifacts (`core/runner.js:206-209 @ 3b399f6`, `core/runner.js:227-231 @ 3b399f6`). A failed audit becomes an "error" result, and the other audits still run. Informative and not-applicable audits get weight 0 (`core/scoring.js:63-68 @ 3b399f6`). Lighthouse also simulates a slow phone from a fast run and reports an optimistic and a pessimistic estimate. The trade-off: these are lab numbers from one load, so label each one as observed or simulated.

</Depth>

To reach a panel fast, open the Command Menu, a search box for DevTools commands: press `Ctrl+Shift+P` (`Cmd+Shift+P` on a Mac) and type its name.

<Depth level="production" title="Command Menu, Snippets and Sensors">

The Command Menu works like the Command Palette in VS Code. You type "sensors" and select Show Sensors, so you do not search through nested menus. Delete the `Run >` prefix, and it opens files instead.

Snippets are scripts that you save in Sources > Snippets. A snippet runs in the JavaScript context of the current page, on any page. Use one for a check that you repeat, so you do not paste the same code into the Console again. The trade-off: DevTools keeps snippets in your local preferences. It does not sync them, and they are not files, so copy important ones into your repository.

The Sensors panel overrides geolocation and simulates device orientation, so you test a location bug without travel or a phone. A failure mode: an override that you forget makes the page read a fake position. Practice: set a custom latitude and longitude, then select Location unavailable and check the error state of your page.

</Depth>
