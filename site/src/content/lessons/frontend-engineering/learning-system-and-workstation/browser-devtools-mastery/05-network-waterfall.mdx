{/* <!-- concept: network-panel --> */}

A slow page looks the same whether DNS, the server or a large file caused it. The **Network panel** records every request while DevTools is open, so open it before you reload.

{/* <!-- concept: waterfall-timing-phases --> */}

The **waterfall** column draws each request as a bar in time order. The Timing tab of one request splits that bar into **phases**: Queueing, Stalled, DNS Lookup, Initial connection, Request sent, Waiting (TTFB, time to first byte) and Content Download. The longest phase names the step that lost time.

{/* <!-- concept: network-throttling-and-blocking --> */}

In the lab, load Slow 4G or a slow server. Predict which bar grows, then step through.

<Experience id="network-waterfall-lab" />

A long Waiting bar points at the server or the round trip. A long Content Download bar points at payload size or network speed. A long Queueing bar points at too many competing requests. The **Throttling** menu (Fast 4G, Slow 4G, 3G, Offline) shows a warning icon while it is on. A failed request names its cause in the **Status** column: `CORS error` (a cross-origin refusal), `(blocked:origin)` or `(failed)` with a message. Hover the status for a hint.

The lab leaves out cache state. Repeat visits load files from the browser cache, so tick **Disable cache** to reproduce a first visit.

{/* <!-- concept: initiator-and-priority --> */}

{/* <!-- concept: har-export --> */}

The **Initiator** column names what started a request: Parser, Redirect, Script, Early Hints or Other. Hold Shift and hover a row: initiators turn green, dependencies red. **HAR** (HTTP Archive) is a JSON file of the session that a teammate can drag into their own Network panel. By default it leaves out `Cookie`, `Set-Cookie` and `Authorization` headers.

<Depth level="internals">

DevTools computes HAR phases instead of copying timestamps. Each phase starts at `-1` (not applicable) or `0`. SSL sits inside connect, so the total counts it once, and a request with no response puts all time in blocked (`front_end/models/har/Log.ts:265-353 @ 572bfc0`). Chrome-only data rides in underscore fields such as `_initiator`, `_priority` and `_fromCache` (`front_end/models/har/Log.ts:150-199 @ 572bfc0`).

</Depth>

<Depth level="production">

Teams attach HAR files to bug reports, so the defaults matter. Settings > Preferences > Network > "Allow to generate HAR with sensitive data" adds the secret headers back; share such a file only with people you trust. DevTools also treats an imported HAR as untrusted input and rejects malformed fields (`front_end/models/har/Importer.ts:185-195 @ 572bfc0`).

To reproduce a bug outside the page, right-click the request and pick Copy > Copy as cURL or Copy as fetch. The command carries the same URL and headers, so you can run it in a terminal, or edit the `fetch()` call in the Console and press Enter to resend it. More filters > Blocked requests then shows only the requests that the page blocked.

</Depth>
