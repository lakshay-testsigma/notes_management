Built-in DevTools shows the DOM. It does not show the React components, the Redux state or the accessibility errors behind that DOM. Without help, you read raw markup and guess. A browser extension is a small program that adds features to the browser. A frontend toolkit is a short list of extensions that add DevTools panels or check a page for you.

Every extension has the same parts. `manifest.json` is the one file that every extension must have. It lists the parts and the permissions that each part gets. A content script is the part that runs inside a page and reads or changes its DOM. A DevTools page is the part that adds a panel to DevTools. A background script reacts to browser events and holds shared state. The parts talk by messages.

<Diagram id="how-it-works" />

Follow the arrows in the diagram. Only the content script touches the page. So the manifest tells you what data a tool can read. A content script that matches every site can read every page you open, including your bank and your admin console.

**Note.** Install fewer extensions, and read each manifest first. Check the host permissions, which are the sites a part may run on. A checker that runs only on the tab you click (`activeTab`) can read far less than one that matches all sites.

<Depth level="internals" title="Isolated worlds and injection">

A content script runs in an isolated world. It shares the page DOM but not the JavaScript variables of the page scripts. It cannot call page functions directly; it exchanges messages with them through `window.postMessage()`. Chrome lets you inject a content script in three ways: static declaration in the manifest, dynamic registration with `registerContentScripts`, or programmatic injection with `executeScript`. Programmatic injection needs a host permission or `activeTab`. The `run_at` key sets the timing: `document_start`, `document_end` or `document_idle`, the default. Manifest V3 allows only a non-persistent background script, which loads for an event and unloads when idle.

</Depth>
