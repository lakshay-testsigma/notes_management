Is your release page usable for a person who cannot see the screen, or who uses only a keyboard? A manual review of every element is slow.

An accessibility extension runs rules against the page DOM and lists the elements that break them. Many use axe-core, an open-source rule engine. Teams run them on each release, because a check takes seconds.

Take color contrast. The contrast ratio compares the brightness of text with the brightness of its background. WCAG 2.2 level AA asks for 4.5:1 for normal text and 3:1 for large text.

axe-core has three results, not two. A check can pass, fail as a violation, or return "incomplete". Incomplete means the machine cannot decide. The reason is the axe-core goal of zero false positives (`README.md:71 @ e80f6b7`).

{/* <!-- concept: headings-and-landmarks --> */}

Structure is the second check. Headings should nest by rank: an `h2` follows an `h1`, and you do not skip from `h2` to `h4`. axe reports a skipped level as a best-practice issue, not a WCAG failure. Landmarks are page regions that a screen reader user can jump to. The elements `header`, `nav`, `main`, `aside` and `footer` mark them. WAVE from WebAIM, on the W3C list of evaluation tools, shows them on the page.

In the lab, change the colors and the heading levels. Predict which rules fail first.

<Experience id="a11y-checks-lab" />

**Note.** Automated checks find only some problems. No rule can tell you whether a keyboard user reaches every control in a sensible order, or whether a screen reader announces the page well. Test those by hand on every release.

<Depth level="production">
When a page has several `nav` regions, give each one a label, so a screen reader user can tell them apart. The axe `heading-order` rule has the tag `best-practice`, so a skipped level is advice, not a WCAG failure. Check the heading outline and the landmarks in WAVE or another checker on the W3C list.
</Depth>

<Depth level="internals">
axe-core computes contrast the way the browser paints. It walks the stack of elements under the text, blends the layers from the bottom up, and includes text shadow and opacity. Then it rounds the ratio down, so 4.499:1 never shows as a pass, because WCAG allows no rounding up. A background image, an overlap, a one-character text or an empty field becomes incomplete, not a failure. See `lib/checks/color/color-contrast-evaluate.js:120-154 @ e80f6b7` and `lib/core/base/rule.js:272-287 @ e80f6b7` in the axe-core repository.
</Depth>
