The Elements panel shows a `div` inside a `div`, but not the React component that made it. A framework devtools extension answers that question directly, because it reads the framework's own data from the page.

React DevTools adds two panels. The Components panel shows the component tree, which is the nesting of your components. Select one to read and edit its props and state. The Profiler panel records commits. A commit is one update that React applies to the page. For each commit, the Profiler shows which components rendered and how long each one took.

Why do components render? A render starts for two reasons: the first render of the app, or a state update in the component or in one of its ancestors. Rendering is recursive, so the children of that component render too. Then React changes the DOM only where the new result differs from the old one.

Redux DevTools does the same for a Redux store, which is one object that holds the app state. The extension shows the history of state changes and supports time-travel debugging, so you can see the state at an earlier point. `configureStore` sets `devTools` to true by default.

Angular and Vue ship their own devtools extensions with a component tree. The framework sections of this roadmap teach them.

Before you open the lab, commit to a prediction.

<PredictReveal
  prompt="A parent component holds a counter. It passes the counter to child A only. Child B gets no props. You click the button and the Profiler records one commit. Which components render in that commit?"
  options={["Only child A", "The parent and child A", "The parent, child A and child B"]}
  correct={2}
  answer="The parent, child A and child B all render."
  reasoning="The parent's state changed, so the parent renders again. By default React also renders every child of that parent, even child B whose props did not change. The Profiler makes this visible, so you can see work that a log line would not show."
/>

In the lab, change a prop or dispatch an action. Watch which nodes of the tree change, then read the state history of the store.

<Depth level="production">
Pass `devTools: false` to `configureStore` when a build must not connect to the extension. Use the React DevTools browser extension for Chrome, Firefox and Edge. For Safari and other browsers, run the standalone `react-devtools` package and add its script to the page head. In Redux, `devTools` can also take an object: it names the store, turns on action traces, and sanitizes actions before the extension shows them.
</Depth>
