The Elements panel shows a `div` inside a `div`, but not the React component that made it. A framework devtools extension shows three things that the DOM hides: the component tree, the renders, and the store actions.

React DevTools adds two panels. The Components panel shows the component tree, which is the nesting of your components. Select one to read and edit its props and state. The Profiler panel records commits. A commit is one update that React applies to the page. For each commit, the Profiler shows which components rendered and how long each one took.

A component renders on the first render of the app, or after a state update in it or in an ancestor. Its children render too.

Redux DevTools does the same for a Redux store, which is one object that holds the app state. An action is a message that asks the store to change. The extension lists each action and the state after it, and supports time-travel debugging, so you can see the state at an earlier point. `configureStore` sets `devTools` to true by default.

Use the three views to trace a bug. A list shows the wrong items. Read the action list to find the action that changed the state. Then select the component in the tree and check its props.

Later framework sections of this roadmap cover the devtools of other frameworks.

<Depth level="production">
After a render, React changes the DOM only where the new result differs from the old one. Pass `devTools: false` to `configureStore` when a build must not connect to the extension. Use the React DevTools browser extension for Chrome, Firefox and Edge. For Safari and other browsers, run the standalone `react-devtools` package and add its script to the page head. In Redux, `devTools` can also take an object: it names the store, turns on action traces, and sanitizes actions before the extension shows them.
</Depth>
