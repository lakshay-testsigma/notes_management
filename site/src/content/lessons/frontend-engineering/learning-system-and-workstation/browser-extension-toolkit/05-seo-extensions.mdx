Your single-page app sets the page title with JavaScript. View source shows an empty `<title>`. Will the page show up in search with no title?

Google reads a page in stages. First it fetches the server response: the status code and the source HTML. The source HTML is the raw text the server sends. A status code tells Google that a page is fine, missing, or moved to a new URL by a redirect. Later, a headless Chromium browser runs the JavaScript. The result is the rendered DOM, the page after scripts ran. Google indexes that rendered result.

<Diagram id="seo-read-points" />

The diagram shows which tool reads which stage. View source reads only the source HTML. An SEO extension reads the page DOM, so it sees the title, the robots meta tag and the structured data that scripts added. Structured data is a JSON-LD block that describes the page to search engines. The benefit over view source is clear: you see what Google indexes, not only what the server sent.

**Note.** A tool that reads the DOM does not see the raw response. Check the status code and any redirect in the server response, too. A single-page app can show an error view with status 200. That is a soft 404. Fix it with a JavaScript redirect to a URL that returns a real 404, or add `noindex` to the error view.

Redirects need the raw responses, too. A redirect-path extension lists each hop: its status code and the URL it sends you to. Several hops in a row make a redirect chain.

<Depth level="production" title="Permanent, temporary and chained redirects">
Google prefers server-side redirects. A 301 or 308 is permanent: it tells Google that the target is the canonical URL. A 302, 303 or 307 is temporary: Google keeps showing the source URL. A JavaScript redirect works only if rendering succeeds, so Google may never see it. Googlebot follows at most 10 hops. Google advises fewer than 5 hops, ideally no more than 3, so point each old URL straight to the final destination. After a site move, keep the redirects for at least one year.
</Depth>
