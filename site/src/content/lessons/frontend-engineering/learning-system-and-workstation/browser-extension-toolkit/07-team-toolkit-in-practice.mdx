Two more helper families ask for real power, so judge them by their mechanism.

A design or CSS helper is an extension that inspects or changes styles on a live page. It works through a content script, the extension part that runs inside the page. Use it to test a spacing or color change on the live page, with no rebuild. The risk: a script that matches every site can read every page.

An API or data helper changes network requests. In Chrome, the `declarativeNetRequest` API lets an extension declare rules, and the browser applies them. With a rule you can add an auth header, or send an API call to a mock, without a change to app code or a proxy server.

A team profile is the short list of extensions that the whole team installs.

## Your starting toolkit

- React DevTools: the component tree, props and renders. Access: the pages you debug.
- Redux DevTools: the action list and the store state. Access: the pages you debug.
- An axe-core based checker: violations and incomplete results. Access: the page you check.
- WAVE: errors, headings and landmarks drawn on the page. Access: the page you check.
- Retire.js: library versions with known vulnerabilities. Access: the scripts that pages load.
- The Lighthouse and Performance panels: audits and live metrics. Built in, so no extension permission.

<Depth level="internals">
A content script can be declared in the manifest, registered at run time, or injected on demand; injection needs host permission or `activeTab`. A rule can block, redirect, allow, upgrade the scheme, or modify headers. A `modifyHeaders` rule has three operations. `set` replaces a header, `append` adds a value (only for an allowlisted set of request headers), and `remove` deletes every value of the header. The permission also matters. `declarativeNetRequest` shows an install warning to the user. `declarativeNetRequestWithHostAccess` shows no such warning, but the extension then needs host permission for the sites it changes. Caps: 5,000 session rules, 30,000 dynamic safe rules and 50 enabled static rulesets.
</Depth>

<Depth level="production" title="The API and design workflow">
First, read the API response as a formatted tree, in the Network panel or a JSON viewer extension. A GraphQL inspector is a similar example for GraphQL calls. Next, mock or rewrite the request. A `redirect` rule sends the API call to a mock URL, and a `modifyHeaders` rule sets a header such as an auth token. Requestly is one example of a tool in this family. For design, a content script reads the page DOM and draws an overlay on top, so you can measure fonts and spacing. VisBug and WhatFont are examples. Each step needs a manifest review first.
</Depth>
